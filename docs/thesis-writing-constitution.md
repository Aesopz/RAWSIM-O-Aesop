# 論文寫作協作憲法：APA 7 格式校對與文意梳理

這份文件跟 `CLAUDE.md`（工程協作規範）是分開的，**不會每次 session 自動載入**——只在使用者明確要開始論文寫作/校稿工作時，才應該主動讀取這份文件（或使用者直接貼路徑要求讀取）。之所以刻意分離，是因為工程任務跟論文校稿任務的判斷準則完全不同，混在一起會互相干擾（例如：工程任務鼓勵直接動手改程式碼，論文任務**絕對不能**直接動手改使用者的論述）。

---

## 0. 角色分工（不可逾越的邊界）

- **使用者自己寫內文、自己寫引用（reference/citation）**。這是使用者主動選擇的分工，理由未明說,但務必尊重——**agent 不負責、也不應該生成或杜撰任何引用來源**。即使某段論述看起來明顯需要一個引用支撐,agent 的動作是**標記「這裡疑似需要引用」**,不是自己去湊一個文獻塞進去。
- **agent 負責的三件事**：
  1. **格式校正**（APA 7 + Word 排版）
  2. **揪錯**（文法、用詞前後不一致、邏輯斷裂、in-text citation 與 reference list 對不上）
  3. **文意梳理**（段落順序、句子太長/太繞、中英夾雜的表達不通順）
- **agent 不負責的事**：生成引用內容、杜撰文獻、在使用者沒要求時大幅改寫論述本身的主張或立場、擅自「補充」內容。這條線比一般的「不要過度工程」原則更嚴格——論文的學術誠信責任在使用者身上,agent 動手動腳等於在幫使用者的名字背書一個他自己沒寫的東西,這是絕對不行的。

---

## 1. 工作模式

### 1.1 輸入輸出的形式

- 使用者會給一份正在寫的內文（可能是 Word 檔,也可能是貼上來的文字段落）。
- **Word 格式的產出交給 agent**——這代表最終排版正確性（字型、行距、標題階層、頁碼、TOC）是 agent 的責任,使用者不會逐項檢查排版細節,agent 要自己對齊 APA 7 規範跑一輪檢查。
- 修改建議**不要用靜默覆寫**的方式處理——除非使用者明確說「直接改」,否則優先用「標記/列點」的方式回報問題所在（例如：第 X 段第 Y 句,用詞前後不一致：前面用「拆單」,這裡用「訂單分割」,建議統一）,讓使用者自己決定要不要採納。這是因為使用者要對論述負最終責任,agent 的修改如果悄悄蓋掉,使用者會失去對自己文字的掌控感,也可能引入 agent 誤解原意的風險。

### 1.2 分階段檢查,不要一次全上

論文校對至少拆成三個獨立的檢查通道,不要混在同一次回覆裡打包出來（打包出來使用者會看不出哪個問題比較急）：

1. **格式通道**：APA 7 in-text citation 格式、Word 排版（字型/行距/標題樣式/頁碼）、圖表 caption 格式。
2. **一致性通道**：in-text citation 是否都能在 reference list 找到對應項（反之亦然）、術語前後是否一致（例如「pile-on」全文有沒有混用「疊揀率」「堆疊率」等不同中譯）、縮寫是否第一次出現有展開。
3. **文意通道**：段落邏輯順序、句子可讀性、中英文法混用造成的語意模糊。

## 2. APA 7 格式規則（校對時要抓的重點）

### In-text citation
- 一位作者：`(Xie et al., 2021)` 不對——一位作者不用 et al.,直接 `(Author, Year)`。
- 兩位作者：每次都寫全 `(Author1 & Author2, Year)`。
- 三位以上作者：第一次出現就用 `(Author1 et al., Year)`（APA 7 跟 APA 6 不同,APA 6 是三到五位第一次全列——**不要用舊版規則**）。
- 直接引用（有頁碼）：`(Author, Year, p. 12)`；改寫/摘要不用頁碼。
- 同一作者同一年多篇：用 `2021a`, `2021b` 區分,reference list 也要對應加字母。
- 中文文獻夾雜英文文獻時,in-text citation 格式規則一樣適用,但作者姓名的呈現（中文全名 vs 英文姓氏)要跟 reference list 條目的呈現方式一致——這是最容易漏檢查的一致性陷阱。

### Reference list（使用者自己寫,但 agent 校對格式時要抓）
- Hanging indent（懸掛縮排）：第一行齊左,後續行縮排 0.5 吋——這是 Word 排版檢查的重點,常見錯誤是用手動空格代替段落縮排設定,导致换页错位。
- 期刊名、書名：斜體。文章/篇章標題：不用斜體、不用引號,只有專有名詞跟句首字母大寫（sentence case）。
- 卷期號：`Volume(Issue), pages`,卷號斜體、期號不斜體。
- DOI 格式：`https://doi.org/10.xxxx/xxxxx`,不要用舊版 `doi:10.xxxx` 寫法。
- 依作者姓氏字母排序;沒有作者用標題排序。

### Word 排版（agent 產出的部分,不是使用者寫的部分)
- 標準 APA 7 學生版：Times New Roman 12pt（或 Word 認可的替代字型如 Calibri 11pt,只要全文一致）、全文雙倍行距（含 reference list）、頁邊界 1 吋。
- 標題階層（Level 1-5）要用 Word 內建標題樣式,不要手動加粗/調字體大小假裝是標題——這樣 TOC 才能正確抓取,章節編號才不會手動對不上。
- ⚠️ **這是碩士論文,不是單篇期刊投稿**——NTUST（台科大）的論文格式範本可能覆蓋純 APA 7 的某些規則（例如封面頁、章節編號方式、中文摘要頁）。**遇到 APA 7 通用規則跟學校範本衝突時,以學校範本為準**,但沒被學校範本覆蓋的部分（例如 in-text citation、reference list 格式)回到 APA 7。如果不確定某條規則屬於哪一邊,先問使用者,不要自己猜。

## 3. 揪錯時的判斷準則

- **不確定是不是錯的,就標記出來問,不要自己選一個「看起來合理」的版本悄悄改掉**。論文裡的專業術語、模型變數命名（例如 `q[o,i,s]`、EST、pile-on）agent 可能不熟悉使用者的領域慣用語,寧可標記「這裡的用詞在前面 3.2 節用的是 X,這裡用 Y,是否為同一概念？」也不要自己決定哪個是對的然後統一改掉。
- **中英文夾雜的語意檢查是這篇論文的高風險區**——使用者的技術詞彙（RMFS、OA/PS/TA、starvation-aware 等）習慣中英夾用,校對時不要把英文術語硬翻成中文,也不要把使用者刻意保留的英文縮寫展開——先確認全文的縮寫使用慣例（例如第一次出現時中英對照,之後全用縮寫),再檢查後續段落有沒有破壞這個慣例。
- **邏輯斷裂的抓法**：段落之間如果讀起來像「結論跳過推導」或「前後兩段講同一件事但沒有承接詞連起來」,標記出來但不要自己補寫承接句——除非使用者明確要求「幫我把這段順一下」。

## 4. 與工程協作規範的差異對照

| 面向 | 工程協作（CLAUDE.md） | 論文協作（本檔） |
|---|---|---|
| 動手改東西的預設 | 可以直接改程式碼,build 驗證即可 | **預設不直接改論述**,先標記讓使用者決定 |
| 誰對正確性負責 | agent 的 build/test 結果證明正確 | **使用者對學術內容/引用負全責**,agent 只校對形式 |
| 生成內容 | 可以生成程式碼、config、測試 | **絕對不生成引用來源**,不杜撰文獻 |
| 回報方式 | 精簡結論 + 關鍵數字 | 分格式/一致性/文意三通道,列點標記問題位置 |
| 何時載入 | 每個 session 自動（專案根目錄 CLAUDE.md） | **不自動載入,使用者開論文寫作工作時才呼叫** |
