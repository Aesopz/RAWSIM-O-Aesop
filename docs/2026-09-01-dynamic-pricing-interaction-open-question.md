# 未解問題：自我校準定價為何在「不可拆單」下反而更糟

**日期**：2026-09-01
**狀態**：交互作用已由實驗確立；**成因未知**
**影響**：決定論文能不能宣稱「動態定價是更好的設計」

---

## 1. 背景：M4G 的價格是量測來的，不是調出來的

M4G 是一個線上聯合最佳化模型，每當揀貨站釋出槽位就觸發一次決策，一次同時決定
OA（訂單指派）、PS（貨架選擇）、TA（機器人派工）。目標式是

```
min  D − V
```

- `D` = 本期實際要走的公尺數（機器人→貨架、貨架→站台）
- `V` = 本期掙得的進度，**換算成公尺**

兩者同量綱，相減才有意義。`V` 展開為

```
V = λ [ Σ e(o,i) + β Σ (ê(o,i) − e(o,i)) ]
  + μ [ Σ f(o)   + β Σ (f̂(o)   − f(o))   ]
```

| 符號 | 意義 | 來源 |
|---|---|---|
| `λ` | 每關一條訂單行的距離代價 [公尺/行] | `D_cum / L_cum` |
| `μ` | 每完成一張訂單的距離代價 [公尺/單] | `λ × (L_cum / N_cum)` |
| `β` | 兌現率：估值層宣稱的行，實際被綁定的比例 | `E_cum / Ê_cum` |
| `e, f` | 綁定層：本期真的送進站台的行 / 單 | 決策變數 |
| `ê, f̂` | 估值層：不受槽位限制下能關的行 / 單 | 決策變數 |

**三個價格全部是量測值，沒有任何手調權重。** 兩層（估值 / 綁定）在數學上只差一條
限制式——站台槽位容量 `B3`。`β` 就是這個落差的兌現率。

---

## 2. Dinkelbach 在這裡做什麼

`V` 裡面含 `λ`，所以目標式其實是 `min D − λP`（`P` 是以「行當量」計的進度）。
`λ` 不是題目給的，它是「一條行值幾公尺」的兌換率，必須先有定義才寫得出目標式。

我們把 `λ` 定義成**系統當下自己的邊際率**，也就是 `min D/P` 的最佳值，而求這個
比值的標準工具就是 Dinkelbach：

```
λ ← 歷史累積平均 D_cum / L_cum
重複至多 5 次：
    plan = solve( min D − λP )
    P* = (D* − obj) / λ
    若 P* ≤ 0        → λ ← 2λ 重來（上限 6 次）
    若 |obj| ≤ 0.5   → 停，已打平
    λ_next = D* / P*
    trial = solve(λ_next)
    若 trial 的 P* ≤ 0 → 停，保留舊 λ 與舊解     ← 退化防呆
    採用 λ_next
```

**關鍵性質：`λ` 每一次決策都可能不同。** 它從歷史平均出發，用「上一個解實際達成的
比值」逐次收緊。實測（正典，30 seeds）：

- `λ` 在 65.1% 的決策中有變動
- 單場範圍約 6.3 – 10.0，中位數約 8.18
- 60% 的決策 `λ` 被往下修正，中位數修到原本的 0.37 倍

這就是「每次決策優化的目標都不一樣」的具體意思。

## 3. 想回答的問題

> **透過 Dinkelbach 反求系統定價，相對於 M1G 那種手工寫死權重，
> 前者隨系統狀態變動、後者不管動態資訊，兩者的系統表現差多少？
> 以及，單純開放拆單 vs 不能拆單，差多少？**

為了把兩件事分開，設計成 2×2 因子實驗。

## 4. 實驗設計

### 4.1 四臂

**全部是同一份程式、同一個求解器、同一組符號**，差異只在 config 的幾行。

| | 不可拆單（訂單原子） | 可拆單（訂單行原子） |
|---|---|---|
| **手釘價格** | **A** | **C** |
| **Dinkelbach 自我校準** | **B** | **D** = 正典 |

```
D  正典                m4g.xconf
B  動態 + 不拆         + OrderAtomicNoSplit=true                          （1 行）
C  靜態 + 拆           + LambdaFixed / DeltaFixed / DinkelbachIterations=0（3 行）
A  靜態 + 不拆         + 以上四行                                          （4 行）
```

### 4.2 正典的形態（重要）

正典經過幾次演化，這組實驗跑的是：

- **行級原子**（`LineAtomicSplitting=true`）：一條訂單行必須整條落在同一個站台，
  不能跨站切分。同站台的多台貨架仍可合力供應一條行。
- **精簡編碼**（`CompactLineModel=true`）：件級變數 `q̂, q` 已被消掉，模型直接以
  「行→站台」的二元指示變數表述。貨架對行的分派由事後貪婪還原。
  求解快 3.3 倍，決策 0 的目標值與完整編碼差 1e-14（等價）。
- **`V2a` 已移除**（`IncrementalValuationEnabled=false`）：V2a 是「新派貨架的估值
  只計在途供給蓋不到的那部分需求」的 per-SKU 池化上界。
  實測在正典中對件數與行數**零影響**（1430/1430、951/951），
  但在訂單原子臂中造成 −4.2% 件數的傷害（量綱不對齊：粗於原子的聚合上界會誤傷），
  故從兩邊一併移除。

### 4.3 不可拆單臂的定義（M1G 語意）

這一臂**不是**「正典加一條禁止跨站的限制式」，而是把**原子從『行』改回『整張訂單』**，
也就是 M1G 的指派語意。依據是 M1G 的 `shi5`：

```
shi5   Σ_{o 需要 SKU i} PositionOverallCount(o,i) · yos(o,w)
         ≤ Σ_{p 有 SKU i} CountAvailable(p,i) · xps(p,w)
```

`PositionOverallCount(o,i)` 是**整張單對該 SKU 的完整需求**，所以 `yos(o,w)=1` 的
那一刻，這張單的全部需求就必須被派到 `w` 的貨架總庫存蓋住。**M1G 的 MILP 裡沒有
「半張單」這個物件。**

精簡後的正典 `V1'` 與 `shi5` 是同一個聚合形式，只差原子是「行」還是「整單」：

```
M1G  shi5    Σ_o d(o,i)·yos(o,w)   ≤ Σ_p s(p,i)·xps(p,w)
正典 V1'     Σ_o d(o,i)·ĝ(o,i,w)   ≤ Σ_p s(p,i)·z(p,w)
```

因為指派蘊含全覆蓋，assigned order 的每一條行都會關閉，即 `e ≡ f`。所以在這一臂
**`λ` 項是冗餘的**（是 `μ` 項的重述），已從目標式移除，`β` 改由訂單計價
（bound orders / valued orders）。

實作查核（30 seeds 等級）：
- `boundLines = valuedLines = 0`（確認無 line 物件）
- 部分履行決策 = 0（確認整單語意成立）

### 4.4 靜態臂的釘定值

**靜態臂拿到的是該模型自己的長期量測平均值**，不是隨便選的數字：

```
C 靜態+拆     LambdaFixed 8.1737    DeltaFixed 0.1951   （取自 D 的 6 seeds 平均）
A 靜態+不拆   LambdaFixed 14.1176   DeltaFixed 0.6644   （取自 B 的 6 seeds 平均）
```

這是刻意的：**靜態臂擁有「平均而言正確的價格」，唯一缺的是隨狀態調整的能力。**
所以 C→D 與 A→B 量到的是純粹的「適應性」價值，不是「猜對數字」的價值。

已查核釘定值與「實際使用的 λ」對齊（偏差 +0.1%），不是取錯欄位：

```
臂      lambdaStart均   lambda實際均   釘定值      偏差
D          8.1737        8.1619      8.1737    +0.1%
B         14.1176       14.0975     14.1176    +0.1%
```

## 6. 問題

**動態定價在可拆單時明顯有效，在不可拆單時明顯有害。**

```
可拆單   pile-on +22.68%   EOR −16.55%   件數 +2.26%
不可拆   pile-on  −9.04%   EOR  +5.08%   件數 −3.08%
```

直覺上的反對意見（來自使用者）：

> 我把系統動態的資訊納入每期的優化目標，使用更多（或更準確的）資訊，
> 為何沒有帶來更高的效應？**至少退化，也不應該更糟。**

這個直覺的隱含前提是：**在同一個目標函數下，用更好的估計取代較差的估計。**
但 `λ` 不是餵進固定目標的資訊——**它就是目標本身**：

```
靜態臂   每一期都解同一個最佳化問題
動態臂   每一期解一個不同的最佳化問題
```

沒有定理保證「一連串各自最佳化的不同問題」勝過「一致地最佳化同一個問題」。
單調性只在「問題固定、估計變好」時成立。

第二個角度：`λ` 是從過去量的、套用到未來的**落後統計量**，不是當下狀態的觀測值。
若真實的 `λ*` 大致穩定，歷史平均是**變異數更小的估計量**；用最近一次的實績取代它，
等於用低偏差換高變異。系統越穩定，這個交換越不划算。

**⚠️ 以上兩段是候選解釋，不是已驗證的機制。**

## 7. 已排除的可能

| 假說 | 檢驗方式 | 結果 |
|---|---|---|
| 釘定值取錯欄位（用 λ₀ 而非實際 λ） | 比對 `lambdaStart` 與 `lambda` 兩欄的均值 | **排除**，偏差 +0.1% |
| V2a 造成的假象 | 從兩臂一併移除後重跑 | **排除**，方向不變（seed 0 曾看似趨零，5 seeds 後回到明顯為負） |
| λ 根本沒在更新 | 統計 `lambdaEnd ≠ lambdaStart` 的比例 | **排除**，B 臂 74.3% 的決策有更新 |
| 對照組是稻草人（符號不對齊） | 改用 M4G 自己的變數與量測價格重寫 NS 臂 | **排除**，四臂同程式同符號，config 差 1–4 行 |

### 曾經給出但被推翻的機制解釋（引以為戒）

1. **「門檻收緊 → 拒絕更多派車 → 站台更餓」**
   → 實測 λ 是往**下**走（B 有 77.5% 的決策低於 A 的釘定值），且派車數幾乎不變
   （189.3 → 186.2）。**方向就錯了，已撤回。**

2. **「動態定價讓估值層宣稱更少」**
   → 實測 A 在**完全沒有派車**的 3690 次決策裡也宣稱更多。那些決策沒有距離成本
   被權衡，且宣稱在目標式裡是免費的（只有獎勵、無成本），所以價格不可能直接影響它。
   差異來自兩臂的**系統狀態已經分歧**。**這是相關，不是機制，已撤回。**

**教訓**：在這個系統裡，因果幾乎不可能從單一決策的邏輯推到整場模擬的 KPI，
因為兩臂在第一次分歧之後就處於不同狀態，之後所有差異都混著「機制效果」與
「狀態漂移」。任何機制敘述都必須能推出一個**獨立於原指標的可檢驗後果**。

## 8. 建議的下一步

### （一）λ 掃描（不拆單臂）— 便宜、幾乎一定有結論

把 B 臂的 λ 釘在 `12.0 / 13.0 / 14.12 / 15.0 / 16.0`，各 5 seeds。

- 若固定 λ 的曲線在 14 附近有**平緩但不對稱**的最佳點，而動態 λ 在 8.95–15.12
  之間游走時常掉進較差的一側 → 直接解釋「變動反而更糟」
- 若曲線在該區間近乎平坦，則「變異數」的解釋不成立，要另找原因

估計 40 分鐘。

### （二）同快照比較 — 唯一能講因果的方法

固定同一個決策時點的 snapshot，分別用動態 λ 與靜態 λ 各解一次，比較解的內容
（派哪些車、綁哪些單、目標值）。這能把「機制效果」從「軌跡漂移」裡分離出來。
只在系統狀態尚未分歧時有效，也就是每場模擬最初的幾次決策。

### （三）補到 30 seeds

目前是 5 seeds。交互作用的 t 值已經很大（3.4 – 10.4），但先前有過
「3 seeds 看似紮實、5 seeds 掉到 n.s.」的前例，正式數據應補足。

⚠️ 另一個待處理的方法學細節：釘定值取自 seeds 0–5 的平均，而測試也是 seeds 0–4，
屬於同一批種子。嚴謹版本應以不同批種子校準，或取 30 seeds 平均。

## 9. 對論文的處置建議

**不要宣稱「動態定價是更好的設計」**——A→B 為負會直接反駁它。

改成一個更具體、也更難反駁的主張：

> **自我校準定價的價值來自它與拆單的互補：拆單創造了細顆粒的選擇空間，
> 浮動的門檻才有東西可以挑；沒有那個空間時，浮動只會製造雜訊。**

理由：
- 交互作用七項全部顯著，是這組實驗最紮實的數據
- 它**預測了一個反直覺的現象**（不拆單時動態反而更差），並被實測證實
- 一個能預測反直覺結果的敘述，比「我的方法比較好」有份量

A→B 為負不是瑕疵，是這個敘述的**證據**。真正需要補的是機制，
而不是把結論改成原本期待的樣子。

**在補上第 8 節的實驗之前，論文只能報交互作用的存在，不能報成因。**
