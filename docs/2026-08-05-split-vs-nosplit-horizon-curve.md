# 拆單 vs 不拆單：吞吐量差距是 O(1/T) 的在製品效應

2026-08-05。單變數對照實驗，證明「開放拆單的吞吐量劣勢來自在製品，隨模擬時窗按 $O(1/T)$ 收斂」。

---

## 1. 實驗設計

| | |
|---|---|
| 佈局 | `small_10bot.xlayo`（10 台車、2 揀貨站、2 補貨站） |
| 設定 | `small_o100_mu100_{2h,4h,8h}_inv70.xsett`（訂單池 100、庫存 70%、Fill 模式） |
| 時長 | 7200 / 14400 / 28800 秒 |
| Seed | 0（單 seed；見 §6 的效度限制） |
| **拆單臂** | `m4g.xconf` |
| **不拆單臂** | `m1g_a.xconf` |

**兩份 config 逐行比對只差一行**：

```
< <ForbidSplitting>false</ForbidSplitting>
> <ForbidSplitting>true</ForbidSplitting>
```

（`m1g_a.xconf` 少了 `<LegacyObjective>` 一行，反序列化取預設 `false`，與 `m4g.xconf` 的顯式 `false` 同值。）

程式碼層面 `ForbidSplitting` 只出現在 5 個位置，全部是**加限制式**（V7a/V7b/V8/V8g、B8、B9），不碰定價、Dinkelbach、提交路徑或統計。λ/μ/δ/ρ 的計算與校準完全不受影響。

### 1.1 為什麼先前的數據作廢

先前那組 657 vs 608 **不是乾淨的對照**。限制式 `V8g`（「有無法覆蓋的行就不准宣稱完成」）當時只掛在 `ForbidSplitting` 區塊裡，所以**不拆單臂有保護、拆單臂沒有**——而被扭曲的正好是「訂單完成認定」這個被比較的指標本身。

2026-08-04 的 `HonestCompletionReward` 修正把它提成無條件的 `V4g`，兩臂現在都有保護（`ForbidSplitting` 那邊的 `V8g` 成為重複但內容相同的限制式，數學上無害）。本文所有數據皆為修正後重跑。詳見 `docs/2026-08-04-m4g-completion-reward-bug-and-hgs-m5.md`。

## 3. 主結果

| 時長 | **訂單差距** | **件數差距** | 超額在製品÷基準 | **kJ/訂單增益** | kJ/件增益 |
|---|---|---|---|---|---|
| **2 h** | **8.22%** | −0.07% | 9.59% | −26.6% | −32.6% |
| **4 h** | **3.94%** | **+1.56%** | 7.56% | −38.2% | −41.5% |
| **8 h** | **0.94%** | **+2.99%** | 3.40% | −39.4% | −41.8% |

### 3.1 訂單差距按 O(1/T) 收斂

```
8.22%  →  3.94%  →  0.94%
```

每次時長翻倍，差距減半以上，8 小時實質打平。

**超額在製品佔比同步下降**（9.59% → 7.56% → 3.40%），兩欄始終同量級同方向。這坐實了機制：**差距的來源是在製品，不是產能損失。**

### 3.2 件數單調轉正

```
−0.07%  →  +1.56%  →  +2.99%
```

8 小時的拆單多處理 **166 件**（5718 vs 5552）、多處理 **118 行**（3754 vs 3636）。不是「輸得比較少」，是贏，而且三個點方向一致。

### 3.3 能耗優勢穩定在 −39%／−42%

2 小時那個點（−26.6%）偏低，4h／8h 都在 −39% 附近。2 小時太短，拆單的收益尚未完全展開。

機制清楚：**8 小時拆單的載重趟次少 36%（1686 vs 2627）、總距離少 38%（35004 vs 56603）、轉彎少 41%，因為每趟服務的訂單多 96%（pile-on 5.862 vs 2.991）、件數多 104%。**

## 4. 必須誠實標注的三件事

### 4.1 能耗優勢的擴大有一半來自基準自我退化

```
不拆單 kJ/訂單  1.5583 → 1.7766 → 1.8896   （惡化 21%）
拆單   kJ/訂單  1.1439 → 1.0987 → 1.1443   （持平，非單調）
```

拆單自己的能耗**沒有隨時間改善**。三個點全距 4%，落在單 seed 噪音帶內（M4G 五 seed 的 kJ/訂單 全距 5.5%，1.1439~1.2097）。**不要宣稱「拉長時窗讓拆單更省」。**

不拆單的退化本身是可報告的發現，與 memory 記錄的「baseline 隨時間自我退化」現象一致，現在在單變數對照上重現。站台閒置率佐證：不拆單 0.688% → 2.255% → 3.638%，拆單全程穩定在 0.73~0.75%。

### 4.2 在製品不是穩態存量

積壓走 74 → 108 → 92，**沒有收斂到定值**。正確敘述是：**在製品的成長遠慢於產出的成長**（產出 603 → 2421 翻四倍，在製品只漲 24%），所以佔比下降。$O(1/T)$ 結論不變，機制敘述須用此版本。

（先前根據 HGS-M5 的 2h/8h 數據推論「穩態存量約 80」，在 M4G 上不成立，已撤回。）

### 4.3 服務水準的代價隨時窗惡化

| | 2h | 4h | 8h | 成長 |
|---|---|---|---|---|
| 拆單 周轉平均 | 1151 | 1382 | 1825 | +59% |
| 不拆單 周轉平均 | 834 | 926 | 1025 | +23% |
| **拆單 逾期** | 8 | 42 | **159** | **20×** |
| 不拆單 逾期 | 4 | 19 | 66 | 17× |

拆單的周轉中位數（705 → 745 → 841）與不拆單（441 → 378 → 362）**方向相反**：不拆單的中位數在改善，拆單在惡化。訂單雖然最終都做完，但停留時間越來越長。

## 5. 可寫進論文的結論

> **在 8 小時的營運窗口下，開放拆單以近乎相同的訂單完成數（差距 0.94%）與更高的實際產出（件數 +2.99%、行數 +3.2%），達成 39.4% 的單位訂單能耗節省與 38% 的行走距離節省。代價是訂單平均停留時間增加 78%、逾期訂單增加 141%。**
>
> **拆單用「訂單在系統內停留更久」換取「搬運工作量近乎減半」，而非以吞吐量為代價。**

### 5.1 為什麼必須基於 8 小時（口委防禦用）

不要主張「應該用 8 小時」——那是挑時窗。正確主張是：

> **吞吐量差距是一個 $O(1/T)$ 的邊界效應。以下是它對模擬時長的收斂曲線，三個點與「超額在製品 ÷ 基準完成量」的預測同量級同方向。8 小時只是曲線上的一個點，不是被挑選的結論。**

有理論預測 + 三點實測的收斂曲線，「horizon-shopping」的質疑不成立。

## 6. 效度限制

1. **單 seed。** 訂單差距的收斂（8.22 → 3.94 → 0.94）與件數差距的轉正（−0.07 → +1.56 → +2.99）都是單調三點，較可信；但能耗的逐時長變化落在噪音帶內，不可解讀為趨勢。定稿前應補多 seed。
2. **單一佈局與負載。** 10 台車、2 揀貨站、訂單池 100、庫存 70%。跨車隊規模、跨佈局尚未驗證。
3. **Fill 模式。** 訂單由庫存水位驅動生成。Fixed 模式（固定訂單檔）下的複核尚未做。
