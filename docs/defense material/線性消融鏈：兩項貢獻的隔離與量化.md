# 線性消融鏈：兩項貢獻的隔離與量化

**適用問題**
- 你的兩項貢獻各自值多少？怎麼證明不是彼此混淆？
- 拆單與定價哪一個才是主因？
- 為什麼不直接跟 M1G 比？

**一句話**
> 五個階段，相鄰兩階段只異動一個組件。拆單提升吞吐（件數 +9.84%），
> 定價提升效率（相同產出下距離 −21.19%）。兩者性質不同，不可互相取代。

---

## 1. 結論

| 貢獻 | 異動的組件 | 件數 | pile-on | 每單能耗 |
|---|---|---:|---:|---:|
| **一、行級拆單** | 指派指示變數的索引：訂單 → 訂單行 | **+9.84%** *** | **+33.74%** *** | **−14.22%** *** |
| **二、量測驅動定價** | 價值側三個係數的來源：常數 → 量測 | **+0.48%** ** | **+25.40%** *** | **−21.43%** *** |
| 兩者合計 | | +10.36% *** | +67.71% *** | −32.60% *** |

n = 5 配對種子，`***` p<0.01、`**` p<0.05。

**兩項貢獻的性質不同：**

- 拆單是**吞吐**貢獻——把站台餵飽（供給落差 9.77% → 0.81%）
- 定價是**效率**貢獻——站台已飽和，故以相同產出減少 21% 的行程

> ⚠️ 不可宣稱「定價提升吞吐」。件數僅 +0.48%，且該階段起點的站台供給落差已只有
> 0.81%，瓶頸飽和，吞吐無提升空間。正確口徑為「相同產出、少走五分之一的路」。

---

## 2. 五個階段的數學異動

環境：`small_6bot.xlayo`（6 機器人、2 揀貨站、站台容量 6）、
`small_o100_mu100_2h_inv70.xsett`（7200 秒、100 單積壓、70% 庫存）、seeds 0–4。

### S0 · M1G（外部基準）

```
變數    z[p,w]  y[r,p]  ŷ[o,w]  x[o,w]  u[w]
        ŷ = yos（估值指派）   x = yaos（綁定指派）   u = us（空槽）

目標式  min  Σ d·z + Σ d·y  −  40·Σ ŷ[o,w]  +  1000·Σ u[w]

限制式
  shi2   Σ_w ŷ[o,w] ≤ 1                              一張訂單最多一個站台
  shi3   x[o,w] ≤ ŷ[o,w]                             綁定 ⊆ 估值
  shi4   Σ_o x[o,w] + u[w] = C[w]                    槽位等式，u 為鬆弛
  shi5   Σ_o d°[o,i]·ŷ[o,w] ≤ Σ_p s[p,i]·z[p,w]      逐 SKU 逐站台聚合庫存
  shi6   Σ_w z[p,w] ≤ 1

准入    All(每個 SKU 全系統存量 ≥ 原始需求 d°)
```

### S0 → S1 · 移植（**非貢獻**）

限制式形式全部保留（NS1↔shi5、NS3↔shi3、LegacyIdle↔shi4），目標式一字不改。

```
准入    All(存量 ≥ 原始需求)  →  Any(剩餘 SKU 存在於某貨架)
需求    d°[o,i] 原始         →  d[o,i] 剩餘
指示式  Σ_w ŷ[o,w] ≤ 1       →  Σ_w ŷ[o,w] = f̂[o]     等式，防止抽貨不計分
```

**效果**：件數 +4.55% (t=3.78)、每單能耗 −4.86% (t=−6.65)

> ⚠️ 這一步同時異動三個組件，不可歸因於任何單一原因。
> 主因為准入機制不同：M1G 以**前置過濾**排除供不到的訂單，本模型以限制式
> `V4g`（無貨可供 ⟹ f̂ = 0）在目標式中拒絕給獎勵。兩者候選池不可比。
> **因此 M1G 僅作為外部基準，不納入歸因鏈。歸因自 S1 起算。**

### S1 → S2 · 貢獻一：行級拆單

異動的是**指派指示變數的索引，一個下標**：

```
S1   ŷ[o,w]      訂單 o 落在站台 w        Σ_w ŷ[o,w] = f̂[o]
S2   ĝ[o,i,w]    訂單行 (o,i) 落在站台 w   Σ_w ĝ[o,i,w] = ê[o,i]   逐行各一式
                                          ê[o,i] ≥ f̂[o]          合併條件
```

庫存式的加總對象隨之改變：

```
S1   Σ_o d[o,i]·ŷ[o,w]     ≤  Σ_p s[p,i]·z[p,w]      整單一起落
S2   Σ_o d[o,i]·ĝ[o,i,w]   ≤  Σ_p s[p,i]·z[p,w]      逐行各自落
```

新增槽位觸發式（S1 的 x 即指派，S2 需把行連回槽位）：

```
S2   Σ_i d[o,i]·g[o,i,w]  ≤  D[o]·x[o,w]
```

**放寬的是哪一條**：`Σ_w ŷ[o,w] = f̂[o]` 對整張訂單只允許一個 w。
改成逐行之後，**沒有任何式子再把訂單綁在單一站台**。

**機制**：一台貨架可補任何訂單的任何一條行，到站後持續產出。

**效果**：供給落差 9.765% → 0.807%（−91.74%, t=−12.45）

### S2 → S3 · 換目標式（**負值，且極顯著**）

限制式一條不動。僅替換價值側：

```
S2   min  D  −  40·Σ f̂[o]  +  1000·Σ u[w]

S3   min  D  −  λ[ Σ e[o,i] + β·Σ(ê[o,i] − e[o,i]) ]
              −  μ[ Σ f[o]   + β·Σ(f̂[o]   − f[o])  ]
              λ = 335.18   μ = 520   β = 0.0385   （固定）
```

三處結構差異：

| | S2 | S3 |
|---|---|---|
| 行級價格 | 不存在 | `λ` |
| 綁定獎勵 | 間接（`−1000·u` 經 shi4 代數等價） | 直接（`λ(1−β)`、`μ(1−β)`） |
| 空槽懲罰 | `+1000·Σu` | **消失**（`SlotScale = 0`） |

**效果**：件數 −1.52% (t=−10.34)、供給落差 0.807% → 2.517%

> `w3 = 1000` 的功能是把「填滿槽位」變成事實上的硬約束。移除它、換成真實
> 量級的價格後，模型變得保守，站台重新出現飢餓。
> **兩層結構單獨存在時是代價，不是增益。**

### S3 → S4 · 貢獻二：量測驅動定價

目標式形式不動，限制式不動。僅三個係數的**來源**改變：

```
S3   λ, μ, β  為常數

S4   λ = D_cum / L_cum                 每期由歷史累積量重讀
     μ = λ · L_cum / N_cum
     β = E_cum / Ê_cum

     再由 Dinkelbach 於每期收斂：       λ ← D* / P*
     停止條件：再收緊一分，空計畫即勝出
```

**效果**：供給落差 2.517% → 0.540%，優於 S2 的 0.807%

> S3 移除空槽懲罰所造成的飢餓，在 S4 被動態定價修回，且優於使用 `1000`
> 這種壓倒性常數的 S2。差別在於精準定價 vs 暴力填槽。

## 4. 口委問答

**Q：兩項貢獻會不會互相混淆？**

不會。S1→S2 只異動指派指示變數的索引（訂單 → 訂單行），目標式與價格完全相同；
S3→S4 只異動三個係數的來源（常數 → 量測），目標式形式與限制式完全相同。
每一步都是單一組件的變更。

**Q：定價的貢獻只有 +0.48% 件數，值得嗎？**

那一步的起點站台供給落差已只有 0.807%，瓶頸飽和，吞吐無提升空間。
該階段的價值在效率：**相同產出下距離減少 21.19%、每單能耗減少 21.43%**，
兩者 t 值皆超過 27。這是資本支出與營運成本的語言，不是吞吐的語言。

**Q：兩層目標式那一步是負的，為什麼還要它？**

因為它是自我校準的載體。單獨存在時（S2→S3）它使件數降低 1.52%；
但接上量測價格後（S3→S4）淨值為正。兩者是配套，不是兩個獨立的加分項。
只要拆單不要定價是可行的——那就停在 S2，代價是放棄 21% 的行程節省。

**Q：為什麼不直接跟 M1G 比？**

M1G 以前置過濾排除供不到的訂單（`All(存量 ≥ 原始需求)`），本模型以限制式
`V4g` 在目標式中拒絕給獎勵。兩者的候選訂單池不可比，該差異與拆單、定價
均無關。故 M1G 作為外部基準呈現，歸因鏈自 S1（M1G 目標式移植進本框架）起算。

## 附錄：組態與量測定義

| 階段 | 組態檔 |
|---|---|
| S0 | `m1g.xconf` |
| S1 | `m4g_legacy_ns.xconf`（`LegacyObjective` + `OrderAtomicNoSplit`） |
| S2 | `m4g_legacy.xconf`（`LegacyObjective`，拆單開放） |
| S3 | `m4g_m1gfix_B.xconf`（正典 + `LambdaFixed/MuFixed/DeltaFixed`） |
| S4 | `m4g.xconf`（正典） |

M1G 固定價格的換算（無新增自由參數）：

```
M1G 目標式    min Σ距離 + w2·Σyos + w3·Σus      w2 = −40、w3 = 1000
shi4 為等式   Σyaos + us = C[w]
代入          w3·Σus = 1000·ΣC[w] − 1000·Σyaos      前項為常數

⟹ 綁定訂單總計領 1000 + 40 = 1040 公尺
⟹ β = 40 / 1040 = 0.0385

M4G 每張完成訂單同時領 λ·(行數) 與 μ，且正典關係 μ = λκ
⟹ λκ + μ = 1040 且 μ = λκ  ⟹  λκ = 520
⟹ λ = 520 / 1.5514 = 335.18、μ = 520      κ = 951/613 為正典自身的行/單比
```

| 名詞 | 定義 | 來源 |
|---|---|---|
| 站台供給落差 | 站台無貨架可揀、但仍有事可做的時間佔比 | `StatStationStarvationPctOfSimXStations` |
| pile-on | 每次揀貨站到訪服務的訂單數 | `system_order_pile_on` |
| EOR | 每張完成訂單的機械能耗 (kJ) | `energy_mech_per_order_kJ` |

> ⚠️ 完成訂單數不可用於跨臂比較：Fill 模式下各臂投入訂單量不同
> （574.8 / 599.8 / 594.4 / 577.6 / 595.8，無單調性），且拆單產生在製品。
> 主表以件數與行數為準。
