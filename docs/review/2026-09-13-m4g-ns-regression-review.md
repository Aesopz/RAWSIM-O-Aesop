# 審查請求：不拆單模型（M4G-NS）的派車誘因無法從距離比值推導

**日期**：2026-09-13（第二版，取代同日第一版）
**對象**：獨立審查者（無 repo 存取權，本文件為自含）
**專案**：RMFS 訂單拆分之線上聯合最佳化，C# RAWSimO 擴充版

---

## 0. 核心困難（先講結論）

不拆單模型 M4G-NS 用自我校準的比值定價（`min D/F`，F = 完成訂單數），在吞吐上穩定輸給手釘權重的文獻基準 M1G 約 23%。

今天測試了**六個**修復假說，其中五個被明確證偽。倖存的那一個（解耦）把缺口縮到 3%，但它的運作方式是**刻意打破損益兩平、超額支付**——本質上與 M1G 的手釘常數是同一件事，只是傾斜幅度由量測決定。

由此得到的判斷是：

> **綁定（把訂單指派進站）的誘因無法從距離比值推導出來。**
> 綁定之所以重要，是因為不綁定站台就閒置——那是**時間**維度的成本。
> 目標式只有距離維度，所以它結構性地看不見這件事。

**請審查這個判斷是否成立**，以及 §7 的兩個落點是否還有第三條路。

---

## 1. 系統與實驗設定

- **佈局**：`small`，2 揀貨站、2 補貨站、單層。揀貨站容量以**訂單**計。
- **機隊**：6 或 10 台 AMR。兩個 layout 檔除 `BotCount` 外**逐 byte 相同**。
- **時長**：7200 秒（2 小時），初始庫存 70%，Fill 訂單流（消耗即補，維持 backlog = 100 張單）。
- **求解**：Gurobi，每個決策時點重解一次 MILP（線上、滾動視窗、未來訂單未知）。
- **本文所有數據皆為 seed 0 單一種子**，尚未做統計檢定。

## 2. 三個模型的目標式

三者共用**完全相同**的限制式 `shi2`–`shi13`（已逐行比對）。

### 2.1 變數與關鍵限制式

| 變數 | 意義 |
|---|---|
| `x[p,s]` | 貨架 p 送到站 s（只有新派的計距離） |
| `yr[r,p]` | 機器人 r 去取貨架 p |
| `y^v[o,s]`（`yos`） | **估值層**：訂單 o 潛在可由站 s 完成 |
| `y^b[o,s]`（`yaos`） | **綁定層**：訂單 o 實際指派給站 s（觸發 `AllocateOrder`） |
| `u[s]` | 站 s 的空槽數 |

```
shi2:  Σ_s y^v[o,s] ≤ 1                   一張單至多一個站
shi3:  y^b[o,s] ≤ y^v[o,s]                綁定必先估值
shi4:  Σ_o y^b[o,s] == Cs[s] − u[s]       槽位容量，等式
shi5:  Σ_o need(o,i)·y^v[o,s] ≤ Σ_p avail(p,i)·x[p,s]     貨架供給上限
shi7:  已 committed 的貨架 x[p,s] == 1     （因此其供給在 shi5 右手邊是免費的）
```

`D` = 距離項，**只對尚未派出的貨架計費**（沉沒成本不重複計）。

### 2.2 M1G（Jiao 2026，本專案禁止修改此檔）

```
min D − 40·Σ y^v + 1000·Σ u
```

因 `shi4` 是等式，`u = Cs − Σy^b`，代入後：

```
min D − 1000·Σ y^b − 40·Σ y^v   (+ 常數)

⟹ 綁定一張單 領 1040     僅估值一張單 領 40     兌現溢價 26.0 倍
```

三個權重皆由原作者以 preliminary experiments 試出（原文自承長期影響 "cannot be accurately quantified"）。

### 2.3 M4G（拆單，本研究主模型）

`min D/P`，P = 完成的訂單**行**數，以 Dinkelbach 線性化為 `min D − λP`。

### 2.4 M4G-NS（不拆單對照組）

`min D/F`，F = 完成**訂單**數：

```
min D − μ(1−β)·Σ y^b − μβ·Σ y^v

⟹ 綁定領 μ（因 shi3 同時觸發兩項）   僅估值領 μβ   兌現溢價 1/β

μ = 累積距離 / 累積完成訂單數     （公尺/單，量測值）
β = 累積綁定單 / 累積估值單       （兌換率，量測值）
```

實測 μ ≈ 21 公尺/單、β ≈ 0.65 ⟹ **溢價僅 1.54 倍，對比 M1G 的 26 倍**。

## 5. 唯一倖存的機制：解耦，以及它為什麼可疑

```
正典：  min D − μ(1−β)·Σy^b − μβ·Σy^v      綁定 μ、承諾 μβ、溢價 1/β
解耦：  min D − μ·Σy^b       − μ·Σy^v       綁定 2μ、承諾 μ、溢價 2.0
```

無法透過 β 表達（`μ(1−β)=μ` 要 β=0，`μβ=μ` 要 β=1，矛盾），所以是結構改變而非設定。

**結果**：10 bots 件數 −3.0%、m/行 −7.3%（同時逼近吞吐並保有效率優勢）。6 bots 則件數 −5.2%、m/行 +7.4%（效率反而輸）。**交叉點落在 6 到 10 bots 之間**。

**但它有兩個問題**：

1. **守恆律被打破**。μ 校準的分母是完成訂單數 `F`，但目標式付錢給 `f + f̂`。自我校準的定價原本滿足 `μ × F_cum = D_cum`（付出的獎勵總額恆等於總距離，模型被設計成損益兩平）。解耦付出約 `(f+f̂)/f ≈ 2.5` 倍，是**刻意的超額支付**。

2. **因此它與 M1G 的手釘常數同性質**。差別只在傾斜幅度由量測的 `f̂/f` 決定，而非手選。

⚠️ 若把 μ 的分母同步改成 `f + f̂` 以恢復自洽，傾斜就會消失，1378 這個結果預期會縮回 929 附近（未實測，因設計問題未定案而中止）。

## 6. 兩個決定性的機制發現

### 6.1 自我校準的守恆律

```
μ = D_cum / F_cum   ⟹   目標式付出的總獎勵 = μ × F_cum = D_cum
```

**只要 μ 自我校準，付出的獎勵總額恆等於走過的總距離**，目標式的期望值是 `D − D = 0`。

⟹ 模型被設計成**只接受優於歷史平均的趟次**。NS 在 10 bots 拒派 66% 不是缺陷，是這個設計的定義。

⟹ 任何**重新配權**（換分母、調 β、拆變數）都只能改變分配，動不了總水位。M1G 之所以不受此限，是因為它的價格不是自我校準的：綁一張單付 1040 公尺，一趟車只要 25 公尺，**獎勵池是成本池的 40 倍**。

### 6.2 綁定會掐斷一條年金

```
訂單被綁定 ⟹ AllocateOrder ⟹ 離開待處理池 ⟹ 再也不會被估值
訂單不綁定 ⟹ 留在池中 ⟹ 下次決策再被估值、再領一次 μβ
```

實測每張完成訂單被估值的次數：**NS 正典 1.54 次、M4G 行口徑 5.04 次、NS 等額（β=1）8.46 次**。

在等額設定（β=1，綁定與承諾都領 μ）下，綁定把「每期領 μ 的永續年金」換成「一次性領 μ」，而且綁定所需條件是估值的**超集**（多一個空槽）。模型因此幾乎不綁定：綁/估比 0.119、pile-on 0.95、週期中位 1067 秒（正典 310），趟次 217（正典 141）卻只完成 397 件。**不是死鎖，是空轉。**

⟹ **溢價必須嚴格大於 1**，這是模型自身給出的證明。

## 7. 核心困難與兩個落點

若把估值層視為 **cost-to-go 近似**（單位是公尺，近似「未來可省下的公尺數」），那麼正確的會計應該是：

```
首次估值時付 βμ（一次）   +   綁定時付 (1−β)μ   =   μ        不多不少
之後各期重複估值付 0                                        年金消失
```

此時 β 有明確的物理意義：**承諾最終被兌現的機率**，今天量到是 **95.3%**。

**但把 β 設成 0.953 之後，承諾領 0.953μ、兌現只領 0.047μ**——模型光靠承諾就拿到 95% 的價值，綁定幾乎不值錢。

這不是參數沒調好。**因為承諾幾乎必然兌現，「現在綁」與「以後綁」在距離上真的沒有差別。** 綁定之所以重要，是它讓站台有活幹——那是時間成本，而目標式沒有時間維度。

### 落點 A：承認 NS 是效率導向

它最小化每單公尺數，代價是吞吐低 23%（10 bots 實測 m/行 −5.0%、EOR −8.2%）。拆單的貢獻敘述改為「讓同一個效率平衡點落在更高的吞吐上」。零手釘常數；代價是消融鏈第二階明顯輸給 M1G。

### 落點 B：明確引入第二個維度

讓目標式包含站台閒置時間或吞吐下限，並誠實說明這是**外生的政策選擇**（系統要的是吞吐，不是每單最省）。可用物理量表達（站台閒置秒數 × 揀取速率），不必然是手釘常數。

## 8. 具體審查問題

1. **§6.1 的守恆律推導是否正確？** 若正確，是否意味著「自我校準的比值定價**必然**產生邊際化的派車行為」？這是不是文獻上已知的性質（分式規劃在線上滾動視窗下的已知限制）？

2. **§7 的困難是否真的無解？** 是否存在第三條路，能在**不引入時間維度、也不超額支付**的前提下，讓綁定獲得足夠誘因？

3. **解耦（§5）作為論文貢獻站得住嗎？** 它的傾斜幅度由量測的 `f̂/f` 決定而非手選，但本質是超額支付。這比 M1G 的手釘權重「更有原則」還是只是「換個說法的手釘」？

4. **§6.2 的年金效應**是否為線上滾動視窗最佳化的已知病理？現行做法（β 折扣）與「只在首次估值時支付」相比，何者更標準？

5. **拆單與不拆單的重估倍率差異（5.04 vs 1.54）** 是否足以支撐「NS 不完全鏡像 M4G 有物理理由」這個論證？（實測：全額給付在 M4G 是純付出——距離 +4.7%、EOR +5.2%、吞吐零變化；在 NS 卻有效。）

## 9. 可信度與已知缺陷

- **全部為 seed 0 單一種子**，無統計檢定。
- **M1G 位元同一性已破**：為了做 `w3` 與增量估值的消融，我把 M1G 目標式重構成共用運算式，導致 Gurobi **欄位順序改變**（1224 → 1242，距離 11581.0 → 11378.7）。數學等價但多重最優解的破局結果不同。§3 中 M1G 的所有比較都使用**同一建置**的控制臂。此重構需回退為「旗標關閉時走原路徑」以恢復逐位重現性。
- **增量估值的已知鬆散**：覆蓋判定是逐單對 committed 貨架的總庫存比對，未扣除其他訂單已佔用的單位，故兩張單可能被同一批庫存都判為已覆蓋。方向是**少付**而非多付。
- 先前一輪的 NS 數據受兩個缺陷污染（`SlotScale=1` 的空槽價、`DinkelbachEscalations=6` 的 ×2 猜測使 μ 被灌水 32 倍），已全部重跑，本文數據不含此污染。
- 所有 run 皆由 `footprint.csv` 確認控制器代碼、模擬時長 7200 秒與 `BotCount`。
