# M4G 不拆單對照組：訂單原子、正典價格

**日期**：2026-09-14
**狀態**：設計草案，待使用者審閱
**取代**：`M4GNSManager` 作為拆單效益的對照組（該類別保留、不再用於消融鏈）

---

## 1. 目的與原則

建立 M4G 正典的不拆單對照組，使兩者的差異**只有承諾單位**：

```
M4G 正典     承諾單位 = 訂單行（一張單可分多期、多站承諾）
不拆單對照組  承諾單位 = 整張訂單（一次承諾到一個站，不產生子單）
```

三條原則，不得違反：

1. **價格表與正典逐項相同**：λ、μ、δ 的定義、分子、分母、暖機值、分層規則全部沿用。
2. **Dinkelbach 機制與正典相同**：迭代 λ、μ 隨 λ 等比例縮放、迭代次數與容差、上界跳躍。
3. **只對齊正典實際開啟的部分**：`m4g.xconf` 關閉的旗標，一律不帶入。

承諾後，一張訂單由哪些貨架供應、各取幾件，交給讀回段的貪婪分配（ziops），不在最佳化模型內決定。這與 M1G 的分工相同。

---

## 2. 為什麼不用既有方案

| 方案 | 不採用的理由 |
|---|---|
| `M4GNSManager` | 鏡像 M1G 的限制式與另一套價格（μ、β，無 λ），與正典在模型結構、價格、候選集合等 22 處不同。對照結果同時混入拆單與定價兩個變數。 |
| 正典 ＋ 綁定層 B8c（`BindOneStationOnly`） | 仍以行為原子：一張單可只承諾部分行，剩餘行成為子單，下期可綁到他站。不是整單承諾。 |
| `ForbidSplitting` ＋ `WholeOrderDeferredFill` | 整單承諾只發生在讀回段，compact 路徑沒有全有或全無限制；延後的行由選架層取貨架（距離不進目標式），且不計入價格分母，λ 被系統性高估。 |
| `OrderAtomicNoSplit`（現狀） | 承諾語意正確，但移除了 λ 行項、δ 改用訂單口徑，價格與正典不同；上界沿用「關一條行」的計畫，在訂單原子下不是可行計畫。 |

本設計在 `OrderAtomicNoSplit` 的限制式與讀回段之上，**恢復正典價格、改寫上界**。

## 4. 模型

### 4.1 集合（與正典相同的快照）

```
W      有空槽的揀貨站
O      待處理訂單（M1G 的准入規則：每行系統庫存足量且模型內貨架總量足量；緊急單閘門為 M1G 版）
Pb     已承諾貨架（正前往某站、已被機器人占用）
Pa     可新派貨架
Ra     可用機器人
I      SKU；  P_i = 存有 SKU i 的貨架（PiSKU）
```

### 4.2 參數

```
Cs[w]        站 w 的空槽數
need(o,i)    訂單 o 對 SKU i 的剩餘需求
n(o)         訂單 o 的剩餘行數 = |{ i : need(o,i) > 0 }|
avail(p,i)   貨架 p 上 SKU i 的可用量
d(p,w)       貨架到站最短路徑距離；  d(r,p) 機器人到貨架距離
```

### 4.3 變數（沿用 OrderAtomicNoSplit）

```
x[p,w]    ∈ {0,1}     貨架 p 送往站 w                       （xps）
y^r[r,p]  ∈ {0,1}     機器人 r 取貨架 p                      （yrp）
ŷ[o,w]    ∈ {0,1}     估值層：訂單 o 在站 w 可被完成           （oyh）
y[o,w]    ∈ {0,1}     綁定層：訂單 o 承諾到站 w               （y）
f̂[o]      ∈ {0,1}     訂單 o 被估值                          （zh）
f[o]      ∈ {0,1}     訂單 o 被承諾                          （z）
v[i,w]    ∈ ℤ≥0       站 w 上 SKU i 由新派貨架供給的量         （vpa）
```

### 4.4 限制式

**資源層（與正典 R1–R5 相同）**

```
R1   Σ_w x[p,w] ≤ 1                             ∀p            一台貨架至多去一站
R2   Σ_w x[p,w] ≤ Σ_r y^r[r,p]                   ∀p ∈ Pa       新派貨架需要機器人
R3   Σ_p y^r[r,p] ≤ 1                           ∀r ∈ Ra       一台機器人至多取一台
R4   Σ_r y^r[r,p] ≤ 1                           ∀p ∈ Pa       一台貨架至多一台機器人取
R5   x[p,w] = 1，y^r[bot(p),p] = 1               ∀p ∈ Pb 前往 w 已承諾的行程不可更動
```

**承諾層（沿用 OrderAtomicNoSplit 的 NS1–NS4）**

```
NS1   Σ_o need(o,i)·ŷ[o,w]  ≤  Σ_{p∈Pb∩P_i} avail(p,i)·x[p,w] + v[i,w]     ∀i, w
NS1a  v[i,w]  ≤  Σ_{p∈Pa∩P_i} avail(p,i)·x[p,w]                          ∀i, w
NS2   Σ_w ŷ[o,w] = f̂[o]                                                   ∀o
NS3   y[o,w] ≤ ŷ[o,w]                                                      ∀o, w
NS4   Σ_w y[o,w] = f[o]                                                    ∀o
```

- NS1：估值一張單，就要求它**全部**需求在該站被供給覆蓋（M1G shi5 的形式）。
- NS2、NS4：一張單至多一站，且承諾與否由單一變數表示。**這兩條就是「整單、單站」的全部內容。**
- NS3：承諾必先估值。

**正典共用限制式**

```
V4g   若 o 有任何剩餘行的 SKU 不在 PiSKU 中：  f̂[o] = 0          （HonestCompletionReward）
B6z   f[o] ≤ f̂[o]
B3    Σ_o y[o,w] ≤ Cs[w]                                        ∀w
```

正典的 V4、B7（「完成一張單需關閉所有行」）在訂單原子下自動成立，不另外加。

### 4.5 目標式

正典目標式：

```
min  D − λ(1−δ)·Σc − λδ·Σĉ − μ(1−δ)·Σz − μδ·Σẑ
```

訂單原子下，承諾一張單即關閉它的 n(o) 行，所以行項併入訂單變數：

```
min  D  −  Σ_o [ λ(1−δ)·n(o) + μ(1−δ) ] · f[o]
        −  Σ_o [ λδ·n(o)     + μδ     ] · f̂[o]

D  = Σ_{p∈Pa,w} d(p,w)·x[p,w]  +  Σ_{r, p∈Pa} d(r,p)·y^r[r,p]     （與正典相同，只計新派貨架）
μ  = μ₀ · λ / λ₀                                                   （與正典相同）
```

每承諾一張單領 `λ·n(o) + μ`，與正典對「關閉這張單全部行並完成這張單」支付的金額逐項相同。

## 5. 價格（與正典相同的定義，只調整計數來源）

```
λ  = 累積揀貨距離 ÷ 累積關閉行                   暖機（關閉行 < 50）：λ = 10
L̄  = 累積關閉行 ÷ 累積完成訂單                   暖機：2.4
μ  = λ · L̄
δ  = 累積綁定行 ÷ 累積估值行                     暖機：0.05；依 min(|Pb|,3) 分層，每層至少 50 行
```

**計數來源**：

| 計數 | 正典 | 本設計 |
|---|---|---|
| 關閉行、完成訂單 | 讀回段（`:3403`、`:3415`） | 同一段程式，不改。承諾當期全部行被抽取，所以每承諾一張單計 `n(o)` 行、1 張單。 |
| 綁定行、估值行（δ） | `BoundLineKeys`、`ValuedLineKeys` | 訂單原子下沒有行變數，改計 `Σ_o n(o)·f[o]` 與 `Σ_o n(o)·f̂[o]`。 |

`OrderAtomicNoSplit` 現行把 δ 改成訂單口徑（`:3198`），本設計**不採用**，以維持正典的行口徑。

## 6. Dinkelbach（與正典相同）

一次決策內，目標式可寫成 `min D − λ·V`，其中 V 在迭代期間固定：

```
V = Σ_o ( n(o) + L̄ ) · [ (1−δ)·f[o] + δ·f̂[o] ]        L̄ = μ₀/λ₀
```

迭代（沿用 `M4GManager.cs` 的迴圈，不修改）：

```
λ_k ← λ₀；解出 x_k
重複至多 5 次：
    v* ← (D* − Obj*) / λ_k                         = V(x_k)
    若 v* ≤ 0 且未跳躍過：λ_ub ← 上界（§7）；若 λ_ub > λ_k，以 λ_ub 重解並繼續
    若 v* ≤ 0：停止，保留當前解
    若 |Obj*| ≤ 0.5：停止，已收斂
    λ_{k+1} ← D* / v*；重解
    若無解或新解 v* ≤ 0：停止，保留前一解
```

每次求解的讀回結果隨解一起保存（`M4GResult.BoundDraws`），因此不存在「模型物件殘留被拒解」的問題。

**數學敘述**（空計畫可行，故修正標準 Dinkelbach 定理的陳述）：

```
λ ≤ λ*   空計畫最佳，G(λ) = 0        （退化區間）
λ > λ*   非空計畫最佳，G(λ) < 0
λ*       退化區間的右端點 = min { D(x)/V(x) : x 可行且 V(x) > 0 }
```

從 λ* 上方出發，每一步 `λ_{k+1} = D(x_k)/V(x_k)` 是可行解的比值，恆 ≥ λ*，單調下降。試算解退化時，當前執行的計畫即為比值最佳。上界跳躍的作用是在 λ₀ 落入退化區間時，把 λ 移到 λ* 上方。

## 7. 上界跳躍（唯一需要新寫的機制）

### 7.1 為什麼要改

正典的上界計畫是「一台新貨架讓某站多關一條行」，其 V ≥ 1。在訂單原子下，「只關一條行」不是可行計畫，由它算出的值不保證是 λ* 的上界；若它低於 λ*，跳躍後仍在退化區間，決策會停在空計畫。

### 7.2 新上界

任取一個可行的非空計畫 x，都有 `λ* ≤ D(x)/V(x)`。本設計窮舉的計畫族是：

```
在站 w（Cs[w] > 0）承諾訂單 o，
使用 w 上已承諾貨架的庫存，加上若干台新派貨架補足缺口

V(計畫) = n(o) + L̄
λ_ub    = min_{o,w}  ( D(計畫_{o,w}) + τ ) / ( n(o) + L̄ )        τ = DinkelbachTolerance = 0.5
```

**為何加 τ（2026-09-14 實測後修訂）**：計畫自身的比值 `D/V` 是有效上界，但在恰好這個價格下，該計畫的目標值為 0，與空計畫平手，求解器可能回傳空計畫。首次實測中，175 次成功跳躍有 166 次（94.9%）落在目標值恰為 0、什麼都沒做。

觸發條件是正典的緊急單閘門（`UrgentOrderGate`）：剩餘時間 < 1800 秒的訂單數 ≥ 空槽數時，候選池只保留緊急單。第一次停擺發生在 t = 1814 秒，正是一小時到期窗的首批訂單變為緊急的時刻；候選池由 100 張降到約 6 張。緊急單正是先前因難以整單承諾而被跳過的訂單，池中沒有其他訂單能被同一批貨架順便估值，V 恰為 `n(o)+L̄`，因而平手；更多訂單隨後變緊急，形成停擺循環。池子正常（100 張）時跳躍後皆有行動。

加入 τ 後，上界計畫的目標值為 `−τ`，嚴格勝過空計畫。τ 取自正典既有的收斂容差，不是新參數；大於有效上界的值仍是有效上界。M1G 不受此影響，因其承諾獎勵（約 1040 公尺）遠大於一趟距離，最佳計畫從不打平。

### 7.3 窮舉程序

```
對每個 o ∈ O（僅限滿足 V4g 者）、每個 w ∈ W：
    缺口[i] ← need(o,i) − Σ_{p∈Pb 前往 w} avail(p,i)，負值取 0
    若所有缺口皆 0：略過
        （此時承諾 o 不需新距離，比值為 0；
          若這樣的 (o,w) 存在，當期不會退化，也不會呼叫上界）
    可用貨架 ← { p ∈ Pa : x[p,w] 變數存在 }
    可用機器人 ← Ra
    D ← 0
    當缺口未補足：
        對每台可用貨架 p，令
            補足量(p) = Σ_i min(缺口[i], avail(p,i))
            成本(p)   = min_{r∈可用機器人} d(r,p) + d(p,w)
        若沒有任何 p 的補足量 > 0，或可用機器人為空：此 (o,w) 不可行，跳出
        選 補足量(p) / 成本(p) 最大的 p
        D += 成本(p)；自缺口扣除 p 的補足量
        移除 p 與其最近機器人
    若缺口補足：候選值 ← ( D + τ ) / ( n(o) + L̄ )
λ_ub ← 所有候選值的最小值；若無候選值，回傳 0（不跳躍）
```

### 7.4 有效性與限制

- 計畫滿足 R1–R5、NS1–NS4、V4g、B3，是可行解，所以得到的值一定是有效上界。
- 貪婪覆蓋不保證最少貨架數。當可用機器人剛好不足時，可能把可行的 (o,w) 誤判為不可行；這只會使上界變鬆或找不到，不會使它無效。
- L̄ 必須與同一次決策的目標式使用同一個值。

## 8. 讀回（沿用 OrderAtomicNoSplit，不修改）

1. 對每個 `y[o,w] = 1`，將訂單展開成各行，依「先已承諾貨架、後新派貨架」的順序貪婪分件（`M4GManager.cs:2811-2856`）。NS1 保證庫存足夠，不足時丟出例外。
2. 分件結果登記為 ziops，新派貨架由其機器人占用並登記前往 w。
3. 因整單在單站被全數抽取，走快速路徑：`target = order`、`AllocateOrder` 移出待處理池，不產生子單（`:3337` 之前的分支條件）。
4. `closedLines += n(o)`、`completedOrders += 1`。

## 9. 與正典的差異清單（實作完成後必須逐項核對為真）

| 項目 | 正典 | 本設計 |
|---|---|---|
| 承諾單位 | 行 | 整張訂單 |
| 承諾層限制式 | B1c、V10c、B12c、V1c、V1cPa、B2c、B4c、V4、B7 | NS1、NS1a、NS2、NS3、NS4 |
| 目標式 | 行項 ＋ 訂單項 | 同金額，行項併入訂單變數 |
| δ 的計數 | 綁定行、估值行 | 同口徑，由 `n(o)` 加總得到 |
| 上界計畫族 | 多關一條行 | 承諾一整張單（多台貨架），價格加 τ |
| 緊急單閘門 | HADGS 版：剩餘 < 1800 秒即為急單；急單數 ≥ 空槽數即接管候選池 | M1G 版：另須每個 SKU 的**所有**持有貨架皆可用量足夠且未被占用；急單數 **>** 空槽總數才接管 |

**閘門改用 M1G 版的理由（2026-09-14 實測後修訂）**：HADGS 版不做可行性檢查，在逐行服務的正典中無害；但在整單承諾下，難以整單覆蓋的訂單正是被跳過直到變急的那些，一旦它們獨占候選池便無計畫可承諾，形成吸收態。10 bots 實測最後 20 分鐘候選池由 100 張降至 2 張，而系統訂單池全程維持 100 張（訂單生成未暫停、庫存 0.68–0.74、新貨架約 91 台）。M1G 版只收做得了的急單，且門檻較高；M1G 在同一時段曾降至 5 張、隨即恢復。

| 訂單准入 | 任一行系統庫存 ≥ 1，且任一行 SKU 由模型貨架持有 | **M1G 版**：每一行系統庫存 ≥ 需求，且模型貨架總量 ≥ 需求 |

**准入改用 M1G 版的理由（2026-09-14 修訂）**：正典的寬准入是為了讓部分有貨的訂單能先逐行服務；整單承諾下這類訂單本來就被 V4g 與 NS1 禁止承諾，進入候選池只會增加恆為 0 的變數與新貨架候選。承諾條件不變。實測：6 bots seed 0 逐位相同，但 10 場中 7 場因候選池改變了求解器的平手選擇而軌跡分岔（單場最大 −4.6%，正負混雜）；5 seeds 配對檢定所有指標皆不顯著（平均差距 ≤ 2.5%），主要結論不變。

其餘——新貨架與機器人候選、資源層、V4g、B3、λ/μ/L̄ 定義、揀貨距離分子、暖機、分層、Dinkelbach 迴圈、ziops 分件——**與正典相同**。

上界計畫族的差異是承諾單位改變的直接後果：正典的計畫在訂單原子下不可行。

## 12. 風險

1. **同時需要多台機器人**：多行訂單可能須一次派 2–3 台車，6 bots 下承諾量可能偏低。M1G 有相同要求且可運作，但需實測。
2. **既有停擺紀錄**：記憶記載「正典 ＋ `OrderAtomicNoSplit` 整場停擺」，當時歸因於 λ 被移除使上界跳躍失效。本設計保留 λ 並改寫上界，但另一個可能原因是「關一條行」的上界在訂單原子下不可行（§7.1）；兩者都由本設計處理，仍需實測確認。
3. **貪婪上界過鬆**：若 λ_ub 遠高於 λ*，Newton 需更多步才能下降，可能在 5 次迭代內未收斂。以決策日誌的迭代次數與 λ 終值監測。
4. **決策內比值過度挑剔**：決策內 Newton 最小化的是當期比值，可能拒絕「優於長期平均、但劣於當期最佳」的趟次。此問題若存在，正典同樣存在，**不在本設計範圍**。
