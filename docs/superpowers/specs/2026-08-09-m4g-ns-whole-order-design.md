# M4G-NS：整單原子的不拆單對照模型

**日期**：2026-08-09
**狀態**：設計定案，待實作
**取代**：`ForbidSplitting` / `ForbidCrossStationOnly` / `WholeOrderDeferredFill` 三個旗標所構成的舊 NS 臂（見 §9 審查結果）

---

## 1. 定位

M4G-NS **不是** M4G 的受限版本，而是 **M1G 的指派結構 ＋ M4G 的自我校準定價**。

這個定位讓消融拆成兩個真正的單變數步驟：

| 步驟 | 變的是什麼 | 不變的是什麼 |
|---|---|---|
| M1G → **M4G-NS** | 目標式：手調權重 → 自我校準定價 | 指派結構＝整單 |
| **M4G-NS** → M4G | 指派原子：訂單 → 件 | 定價哲學＝自我校準 |

現行實作把這兩件事混在一起，因此既有的「定價貢獻 −12.3% / 拆單貢獻 −31.4%」歸因**不成立，須以本模型重做**。

### 1.1 核心語意（使用者定義，2026-08-09）

> 每次派單都是**完整的一張單**。它在該站台被幾台貨架服務都無所謂。
> **最小單位是訂單，不是行。因此定價不能出現行或件作為最小單位。**

拆單的意義是「能不能把一張單部分完成、能不能拆到不同站」。M4G-NS 兩者皆否。

---

## 2. 設計不變量

這四條是本模型的識別特徵，任何實作或後續修改都不得違反：

- **INV-1（原子）** 一張訂單只有兩種狀態：完全未指派，或完全指派給單一站台。不存在部分完成、不存在跨期續填、不存在拆單子單。
- **INV-2（定價粒度）** 價目表**只有訂單粒度的價格**。不存在 λ（每行）、ρ（每件）、ε（每件）。
- **INV-3（件數只作可行性）** 件級變數僅用於表達「這些貨架蓋不蓋得住這張單」，其**目標式係數恆為 0**。單位出現在限制式，永不出現在價格。
- **INV-4（多貨架允許）** 一張單可由該站台的任意多台貨架共同供貨，不設上限。

> INV-2 以**結構**而非設定達成：M4G-NS 使用獨立的價格物件 `M4GNSPricing`，其中根本沒有 λ/ρ/ε 這些欄位。**你無法「不小心」對一行計價，因為那個價格不存在。**

## 3. 集合與參數

| 符號 | 意義 |
|---|---|
| *O* | 待處理訂單（本模型中永遠是完整未動的訂單） |
| *I_o* | 訂單 *o* 需求的 SKU 集合（**僅作可行性描述，非計價單位**） |
| *S* | 尚有空槽的揀貨站 |
| *P^a* | 倉儲區貨架（可新派出，**唯一付路程成本者**） |
| *P^q, P^b, P^p* | 已排隊／在途／處理中的貨架（沉沒成本，路程計 0） |
| *R^a* | 閒置機器人 |
| *d_oi* | 訂單 *o* 對 SKU *i* 的需求（**原始需求**；本模型無殘餘概念） |
| *a_pi* | 貨架 *p* 上 SKU *i* 的可用庫存 |
| *C_s* | 站台 *s* 的空槽數 |
| *D_ps, D_rp* | 貨架→站台、機器人→貨架的估計距離（公尺） |

**與 M4G 的差異**：M4G 用 `snap.Residuals`（殘餘需求帳本），M4G-NS 用原始需求。因為沒有部分完成，就沒有殘餘，也就不需要 demand ledger、不需要 `Order.CreateSplitChild`、不需要 consolidation 事件鏈。

## 4. 決策變數

### 綁定層
| 變數 | 型別 | 意義 |
|---|---|---|
| `y[o,s]` | {0,1} | 訂單 *o* 指派給站台 *s*，佔一個槽位 |

| `g[o,i,p,s]` | ℤ≥0 | **未計價**。SKU *i* 由貨架 *p* 在站台 *s* 分配給訂單 *o* 的件數 |

| 變數 | 型別 | 意義 |
|---|---|---|
| `ŷ[o,s]`, `ẑ[o]`, `ĝ[o,i,p,s]` | 同上 | 解除槽位限制後的假想指派 |

### 共用（物理）層
| 變數 | 型別 | 意義 |
|---|---|---|
| `x[p,s]` | {0,1} | 貨架 *p* 派往站台 *s* |
| `u[r,p]` | {0,1} | 機器人 *r* 搬運貨架 *p* |

## 5. 價目表

**只有兩個數字，且都在訂單粒度。**

| 價格 | 定義 | 單位 |
|---|---|---|
| **μ** | 累積行走距離 ÷ 累積完成訂單數 | 公尺 / 訂單 |
| **δ** | 累積綁定完成單數 ÷ 累積估值完成單數 | 無因次 |

μ 是**直接量測**的，不是 `λ × 每單線數` 推導出來的——後者需要 λ，而 λ 不存在（INV-2）。

**分層 δ**：與 M4G 同鍵 `k = min(|P^b|, 3)`，樣本門檻改為 `DeltaStratumMinOrders = 50`（M4G 是 50 條線）。同鍵是刻意的：定價哲學必須對齊，才能把兩臂的差異歸因到指派原子而非定價方式。

**暖機**：`WarmupOrders` 筆完成訂單之前用 `MuFallback`。`δ` 暖機用 `DeltaFallback`。兩者比值不需釘定——因為只有一個價格，不存在 M4G 那個「ρ/λ 比值被破壞導致零訂單」的失效模式（見 §10 風險 R-3）。

## 6. 目標式

```
min   Σ_{p∈P^a} Σ_{s∈S} D_ps · x[p,s]  +  Σ_{r∈R^a} Σ_{p∈P^a} D_rp · u[r,p]
      − μ(1−δ) · Σ_{o∈O} z[o]
      − μδ     · Σ_{o∈O} ẑ[o]
```

三項，就這樣。

- **成本側**與 M4G 逐字相同：只有 *P^a* 付路程，沉沒貨架免費。
- **價值側**只有訂單完成，並由 δ 劈成綁定／估值兩段——與 M4G 的 T4 同構，但沒有 T3（關行）、T5（ε 破平手）、T6（ρ 貨架層級）。
- `g` / `ĝ` 的目標式係數為 **0**（INV-3）。

### 6.1 Dinkelbach

```
min D − μ · V ，  V = (1−δ)Σz + δΣẑ
μ_{k+1} = D*/V* ，  V* = (D* − obj*)/μ_k
```

⭐ **一個結構優勢值得寫進論文**：M4G 的價值側由 μ/λ、ρ/λ、ε/λ 三個比值決定形狀，必須小心維持「所有價格隨 λ 等比例縮放」才能讓 `V` 形狀固定。**M4G-NS 的價格向量只有一個自由度，所以 Dinkelbach 的線性化是建構上精確的，不需要任何不變量維護。**

雙向升壓比照 M4G：`DinkelbachIterations = 5`、`DinkelbachEscalations = 6`、`Tolerance = 0.5`。

### 6.2 沒有 ε 的後果（已知且接受）

M4G 用 ε 在等值解之間偏好「現在就執行」。M4G-NS 沒有這個價格（每件粒度，違反 INV-2）。等值解由求解器任意選擇。**這是 INV-2 的代價，記錄在案，不以人工 tie-break 補救。**

### 6.3 ρ 沒有訂單粒度對應物（論文可用的發現）

ρ 的語意是「這一件現在不揀，以後要為它再跑一趟」——**天生是件粒度**。在整單原子下：

- 「從沉沒貨架服務比較便宜」**已經被 D 本身捕捉**（T1/T2 只向 *P^a* 收路程）
- 任何「整單的貨架層級」定義都需要一條匯總規則（全部線都來自 *P^p* 才算？過半就算？按件加權？），而**任何匯總規則都是新的人為選擇**，違反零調參原則

⟹ **拆單不只是放寬了限制式，它打開了一個不拆單時不存在的定價維度。** 這是 M4G-NS 缺 ρ 的正當理由，也是論文中「拆單的貢獻」的一部分。

## 7. 限制式

### N 系列 — 整單指派（本模型的核心）

| 編號 | 式子 | 說明 |
|---|---|---|
| **N1** | `Σ_o g[o,i,p,s] ≤ a_pi · x[p,s]`  ∀(i,p,s) | 分配受貨架庫存限制，且該貨架必須真的被派往該站 |
| **N2** | `Σ_p Σ_s g[o,i,p,s] = d_oi · z[o]`  ∀o, ∀i∈I_o | ⭐ **全有全無。整個 NS 語意就是這一條等式。** z=1 ⟹ 全部需求被分配；z=0 ⟹ 全部為 0 |
| **N3** | `Σ_i Σ_p g[o,i,p,s] ≤ (Σ_i d_oi) · y[o,s]`  ∀(o,s) | 在站台取貨即佔用該站一個槽位 |
| **N4** | `Σ_s y[o,s] ≤ 1`  ∀o | 一張單只去一個站台 |
| **N5** | `Σ_o y[o,s] ≤ C_s`  ∀s | **槽位容量。估值層唯一沒有的限制** |
| **N6** | `z[o] = Σ_s y[o,s]`  ∀o | 「被指派」與「被完成」是同一事件——整單原子的直接後果，無鬆弛 |

> N2 是 M4G-NS 與 M4G 的**全部差異**。M4G 對應的是逐行不等式對（B5：`Σq ≥ d_oi·c_oi`），允許逐行、逐期、跨站累積。把它換成整單等式，就得到 M4G-NS。模型 diff 之小是刻意的：這樣「拆單」這個處理變數才真正只有一個。

### V 系列 — 估值層

`ĝ, ŷ, ẑ` 滿足 **N1、N2、N3、N4、N6 的完全相同形式**，**唯獨不受 N5（槽位容量）**。

這與 M4G 的兩層結構同構：估值層只解除槽位，其餘物理限制一條不放。

**V-g（誠實完成獎勵，鏡像 M4G 的 V4g）**：
```
ẑ[o] = 0    若 ∃ i ∈ I_o 使得該 SKU 在本次決策無任何貨架可供
```
沒有這條，求解器可以免費設 `ẑ=1` 領取 μδ。M4G 曾因同型缺陷宣稱完成 826 單、實際 569 單。

### B 系列 — 兩層嵌套

| 編號 | 式子 |
|---|---|
| **B1** | `g[o,i,p,s] ≤ ĝ[o,i,p,s]`  ∀(o,i,p,s) — **逐索引** |
| **B2** | `y[o,s] ≤ ŷ[o,s]`  ∀(o,s) |
| **B3** | `z[o] ≤ ẑ[o]`  ∀o |

保證 δ ∈ [0,1] 是結構必然。

### R 系列 — 貨架與機器人

**與 M4G 逐字相同**：R1（一架一站）、R2（派出需機器人）、R3（一車一架）、R4（一架一車）、R5（已承諾貨架釘死目的地與搬運者）。直接鏡像，不做任何修改。

### 8.2 硬性約束

- 🚫 **不得修改** `M1GManager.cs`、`HADGSManager.cs`、`M4GManager.cs`、`M4GPricing.cs`、`SplitM2eICManager.cs`。M4G-NS 全部以鏡像方式新建，即使造成程式碼重複。
- `M4GNSConfiguration` 繼承 `M1GConfiguration`，使引擎中所有 `is M1GConfiguration` 型別檢查自動通過，**不需碰任何引擎檔案**（前例：`SAM1GConfiguration`、`M4GConfiguration`）。
- 新檔案必須手動加 `<Compile Include>` 到 csproj（net48 legacy，不會自動抓）。
- C# 7.3：out 參數不可被 lambda 捕獲（CS1628），需要時用 `var copy = outParam;` 繞過。
- Build 只能 `MSBuild RAWSimOWithSolverWrapping.sln /p:Platform=x64 /p:Configuration=Release`，且**必須用 PowerShell 工具執行**——Git Bash 會把 `/p:` `/nologo` 當路徑轉換掉（2026-08-09 實證）。
- xconf 以 PowerShell `[IO.File]::ReadAllText/WriteAllText` 產生，並用 `Compare-Object` 驗證只有預期差異行。
- 新增 config 欄位一律**追加在類別末端**（XmlSerializer 順序敏感，順序不符會**靜默忽略**）。

### 8.3 提交路徑

`CommitM4GNS`：對每個 `z[o] = 1` 的訂單，`AllocateOrder(order, station)`，**不建立任何拆單子單**、不呼叫 `Order.CreateSplitChild`、不寫 `splitorders.csv`。訂單離開 `_pendingOrders`，後續由既有機制在該站台服務。

### 8.4 空集合守衛（今日審查所得的教訓，必須內建）

**每一處對「可能為空的過濾序列」呼叫 `LinearExpression.Sum` 都必須有守衛**，且守衛**不可只是 `continue`**——那會讓 `z`／`ẑ` 變成自由變數，求解器免費領 μ。

正確作法：
```csharp
if (vars.Count == 0) {
    wrapper.AddConstr(bin["z_" + order.ID] == 0, "N2z");   // 強制歸零，不是略過
    continue;
}
```

> `LinearExpression.Sum(IEnumerable<Variable>)` 對空序列呼叫 `.First()` 會拋 `InvalidOperationException`（`LinearExpression.cs:28`）。M4G 現行的 `ForbidCrossStationOnly` 就是踩到這個而在第 3 次決策崩潰。

## 9. 審查結果：舊 NS 臂的狀態（2026-08-09）

本 spec 取代的舊機制，審查結論如下：

| 項目 | 狀態 |
|---|---|
| `m1g_a.xconf`（`ForbidSplitting` only） | ⚠️ 能跑，但**同時禁跨站與跨期**＝一次動兩個變數。5 seeds 實測：跨站 0、跨期 0、子片段 0 |
| `m1g_a_xstation.xconf`（＋`ForbidCrossStationOnly`） | ❌ **崩潰**。以當前 binary 重跑，第 3 次決策拋 `Sequence contains no elements`（`M4GManager.cs:880`） |
| `out/xs_ns*` 既有資料 | ⚠️ 前一版 binary 產物（跨站 113 ≈ 拆單臂）。**不可引用** |
| 正典 5-seed 的 NS 臂 | 用的是 `m1g_a.xconf`（舊定義） |

**⟹ 依使用者定義的 M4G-NS，至今沒有產出過任何一個有效資料點。所有既有 NS 相關歸因須重做。**

✅ **正典拆單臂不受影響**：無釘定時 `PiSKU` 保證至少一台貨架、`snap.Cs` 非空，q̂ 恆非空。已發表的 M4G 數字安全。

**建議處置**：`ForbidCrossStationOnly` 與 `WholeOrderDeferredFill` 標記為 superseded；M4GManager 的兩處空集合守衛（`:875` 估值層 V2/V3、`:1305` 綁定層 B5/B6c/B7）仍應修好，因為那是潛伏缺陷。

## 10. 風險

| 編號 | 風險 | 對策 |
|---|---|---|
| **R-1** | 整單全有全無在槽位緊繃時可能過度保守，導致 M4G-NS 弱於 HADGS（違反驗收） | 先跑 5 seeds 觀測。若過弱，**不得靠調參補救**；改為明確定義的變體 `DeferredFill`（訂單佔槽後由後續貨架陸續服務，仍不拆單、不跨站），並在論文中兩者都報 |
| **R-2** | 缺 ε 導致等值解選擇不穩、seed 間變異變大 | 5 seeds 觀測變異數；若確實偏大，如實揭露為 INV-2 的代價 |
| **R-3** | 暖機價格失準 | 只有一個價格，不存在 M4G 那個「ρ/λ 比值被破壞導致零訂單」的失效模式。Dinkelbach 雙向升壓可由下方逼近不動點 |
| **R-4** | `g` 變數數量爆炸（4 維索引） | 與 M4G 的 `q̂` 同維度，規模相當。若成為瓶頸，先量測再處理，不預先最佳化 |

## 11. 驗收

### 11.1 結構驗收（必須全過，否則實作不算完成）

| 編號 | 檢查 | 通過條件 |
|---|---|---|
| **S-1** | 拆單生命週期日誌 | **每張訂單恰好出現一次**：跨站訂單 = 0、跨期訂單 = 0 |
| **S-2** | 拆單子單 | 全場 `isChild` 計數 = 0；`splitorders.csv` 不產生 |
| **S-3** | 價目表 | 決策日誌**不存在** λ／ρ／ε 欄位（結構上不可能，因 `M4GNSPricing` 無此欄位） |
| **S-4** | μ 校準 | 決策日誌的 μ 逐列等於 `累積距離 / 累積完成訂單數` |
| **S-5** | δ 校準 | δ ∈ [0,1]，且等於 `累積綁定完成單 / 累積估值完成單` |
| **S-6** | 空集合 | 建構一個「某訂單本次無任何可行站台」的情境，模型須正常求解且該訂單 z=0，**不得拋例外** |
| **S-7** | 對正典無影響 | M4G / M5 / M1G 的既有輸出逐位不變（新增檔案不應動到任何既有路徑） |

### 11.2 效能驗收（使用者指定）

> **比 HADGS 好一點，但顯著遜於 M5。**

| 對照 | 期望 | 判準 |
|---|---|---|
| M4G-NS vs HADGS | 略優 | 完成訂單為主指標，5 seeds |
| M4G-NS vs M5（大規模）／M4G（小規模） | 顯著遜於 | 5 seeds，\|t\| > 2.776 (df=4) |

流程依既定慣例：**5 seeds 一輪、多輪自我調適、最終 10 seeds 檢定**。

### ⚠️ 11.3 關於效能驗收的方法論聲明

**效能驗收是「對照組可信度的健全性檢查」，不是要達成的目標。**

- 通過 ⟹ 對照組既非稻草人（勝過 HADGS）、拆單也確實有貢獻（遜於 M5）
- **不通過 ⟹ 那是實驗發現，如實報告，不得為了滿足預期而調整模型或參數**

若 M4G-NS ≈ M5，代表拆單在該情境下沒有效益——這是關於**限制條件比模型自由度更主導**的正向發現（可與「同期跨站 0/677 能力休眠」相互印證），不是失敗。

本專案已有多次「新結果比 baseline 差 → 查出是 confound 或真實負結果」的先例，負結果紀律優先於預期。

## 12. 後續：M5-NS
