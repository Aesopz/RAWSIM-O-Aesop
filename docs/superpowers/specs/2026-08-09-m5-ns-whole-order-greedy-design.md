## 1. 定位

四個模型構成一個 2×2：

| | **不拆單（整單原子）** | **拆單（件級原子）** |
|---|---|---|
| **精確（MILP）** | M4G-NS | M4G |
| **貪婪** | **M5-NS ← 本文** | M5 |

M5-NS 對 M4G-NS 的關係，必須與 **M5 對 M4G 的關係完全相同**：

> 同架構、同解空間、同價目表，**唯一容許的差異是貪婪提速**。

因此本 spec 的每一條都由兩件事推導出來：**M4G-NS 的模型**（決定「解什麼」）與 **M5 的貪婪架構**（決定「怎麼解」）。凡兩者衝突處，以「忠實反映 M4G-NS 的目標式」優先——因為 M5-NS 的價值來自它建出的解對 M4G-NS 的 MILP 可行，從而 `obj(M5-NS) ≥ obj(M4G-NS)` 是一個可報告的最佳性間隙。

## 2. 從 M4G-NS v2 繼承的模型（重述，因 v1 spec 的 §2/§7 已被取代）

M4G-NS v2 = **M1G 的決策結構 ＋ 量測價格**。變數與限制式逐條鏡像 `M1GManager.cs:714-771`：

| 變數 | 意義 | 層 |
|---|---|---|
| `x[p,s]` | 貨架→站台 | 共用 |
| `u[r,p]`（M1G 名 `yrp`） | 機器人→貨架 | 共用 |
| **`yos[o,s]`** | 訂單 *o* 在站台 *s* **可被覆蓋**（shi2 一單一站、shi5 貨架覆蓋，**不受槽位限制**） | **估值層** |
| **`yaos[o,s]`** | 訂單 *o* **真的佔用一個槽位**（shi3 `yaos ≤ yos`、shi4 槽位容量） | **綁定層** |
| `us[s]` | 站台 *s* 的閒置槽位數（shi4 的鬆弛變數） | — |

目標式：

```
min   Σ_{p,s} D_ps·x[p,s] + Σ_{r,p} D_rp·u[r,p]
      − μ(1−δ) · Σ_{o,s} yaos[o,s]
      − μδ     · Σ_{o,s} yos[o,s]
      + σ      · Σ_s us[s]                        σ = SlotScale × μ
```

**價目表只有 μ 與 δ**（σ 由 μ 導出，零新增自由參數）。無 λ、無 ρ、無 ε。

⚠️ **重要**：`yos` / `yaos` 這組兩層結構**是 M1G 自己的**，不是 M4G 的移植。M1G 以全額 w2 計價 `yos`，等於隱含設定 δ=1；M4G-NS 改用實測 δ。M5-NS 必須保留這個結構。

## 3. 移動類型

M5 有兩種移動（取線、派車）。M5-NS 也是兩種，但**取線換成指派整單**。

### 移動 A — 指派整單（assign-order）

**動作**：把訂單 *o* 指派給站台 *s*，佔用一個槽位。等價於在 MILP 中設 `yaos[o,s] = 1`（因 shi3，同時 `yos[o,s] = 1`）。

**可行條件**（三者皆須成立，對應 shi2/shi4/shi5）：
1. 訂單 *o* 尚未被指派（shi2）
2. 站台 *s* 尚有空槽（shi4；**硬約束，永不轉成價格**）
3. 站台 *s* 在本期帳本上持有 *o* 的**全部需求**（shi5）

**計分**：
```
Δ_A = − μ(1−δ)        ← yaos 綁定側
      − μδ            ← yos 估值側（因 shi3，綁定必同時估值）
      − σ             ← 填掉一個空槽，免去一次 σ 罰
    = − μ − σ
```

> 📌 **推導說明**：`Δ_A = −μ` 而非 `−μ(1−δ)`，因為 shi3 使 `yaos=1 ⟹ yos=1`，兩項同時計入。
> 這與 M5 的「忠實邊際計分」在結構上一致但結論不同：M5 中一條線在被綁定前已經以 `λδ` 賺著估值分，
> 所以邊際改善是 `λ(1−δ)`；M5-NS 中**一張單能否被估值（yos）與能否被綁定（yaos）受同一組限制式
> 約束，差別只在槽位**——所以要看它在**移動前**是否已被估值層算進去（見 §4 的處理）。

### 移動 B — 派車（dispatch）

**動作**：叫一台 *P^a* 貨架到站台 *s*，由最近的空閒機器人搬運。等價於設 `x[p,s] = 1` 與 `u[r,p] = 1`。

**可行條件**：至少一台空閒機器人（**硬約束**）。

**計分**（必須算淨值，理由與 M5 相同——派車單獨看永遠是純成本）：
```
Δ_B = D_rp + D_ps                              ← 距離成本
    + (它立刻解鎖的 assign-order 移動總和)        ← 用拋棄式帳本貪婪收割
    + (估值信用增量)                             ← 見 §4
```

**接受最負的移動，直到沒有負的為止。** 與 M5 完全相同。

## 4. 估值層（`yos`）的貪婪處理

M4G-NS 的目標式對「可被覆蓋但因槽位滿而未指派」的訂單付 `μδ`。省略這一項的貪婪，優化的就是另一個目標式。

**ValuationSweepNS**（鏡像 `GreedyM5Manager.ValuationSweep` 的角色）：

```
stock ← 綁定完成後剩下的各站台庫存（副本）
foreach order in 掃描順序（緊迫度）:
    if order 已被綁定指派: continue
    foreach s in 各站台:
        if stock[s] 能覆蓋 order 的全部需求:      # shi5，且無槽位限制
            扣除 stock[s]
            valuedOnlyOrders++
            break                                 # shi2：一單一站
```

**計分貢獻**：`− μδ × valuedOnlyOrders`

⚠️ **與 M5 的關鍵差異**：M5 的估值層原子是「線」，M5-NS 的是「整單」，且必須**整單覆蓋**才計入——直接對應 shi5 的整單覆蓋語意。

### 4.1 移動 A 的計分修正（忠實邊際）

若訂單 *o* 在移動前**已被估值層算入**（`yos` 已經是 1，只是沒佔槽），那麼指派它的邊際改善是：

```
Δ_A = − μ(1−δ) − σ        （μδ 那一份原本就已在賺）
```

若移動前**未被估值層算入**（例如該站台原本蓋不住它，是本次派車才蓋住的），則：

```
Δ_A = − μ − σ
```

**實作方式**：在每次計分前先跑一次 `ValuationSweepNS` 取得基準集合，`Δ_A` 依該訂單是否在基準集合中選用上式或下式。這是 M5 「FaithfulMarginal」的直接對應物，**預設開啟**（M5 的 `FaithfulMarginal` 預設已是 true）。

## 5. 空槽價 σ 在貪婪中的處理

M4G-NS 的目標式有 `+ σ·Σ us`，其中 `us` 由 shi4 的等式決定。在貪婪中，`us[s]` 恆等於「站台 *s* 當前剩餘空槽數」，因此：

- 一次成功的 assign-order 移動使某站的 `us` 減一 ⟹ **目標值改善 σ**（已計入 §3 的 `Δ_A`）
- 不需要另外維護 `us` 變數；**它是帳本狀態的函數，不是決策變數**

📌 這是貪婪版比 MILP 版簡單的地方之一，且**不損失任何解空間**：任何 M5-NS 的解，把 `us[s]` 設成剩餘空槽數即為 M4G-NS 的可行解。**這正是 `obj(M5-NS) ≥ obj(M4G-NS)` 成立的前提。**

## 6. 外層 μ 迭代

鏡像 `GreedyM5Manager` 的 λ 迭代，把 λ 換成 μ：

```
μ ← μ₀ ; plan ← BuildPlan(μ₀)
for i in 1..MuIterations:                    # 正典 5
    V* ← (plan.DStar − plan.Objective) / μ
    if V* ≤ 0 and escalations < MuEscalations:   # 正典 6，雙向升壓
        μ ← μ × 2 ; plan ← BuildPlan(μ) ; continue
    if V* ≤ 0: break
    if |plan.Objective| ≤ MuTolerance: break      # 正典 0.5
    μ' ← plan.DStar / V*
    next ← BuildPlan(μ')                          # σ = SlotScale × μ' 同步更新
    if next 退化: break
    plan ← next ; μ ← μ'
```

⭐ **σ 必須隨 μ 同步縮放**（`σ = SlotScale × μ`），否則 `V` 的形狀會隨 μ 改變，`V* = (D*−obj)/μ` 這個回推就會靜默算錯。這是 M4G 那條「所有價格隨主價格等比例縮放」不變量在本模型的對應物——**M4G-NS 只有一個自由度，所以維持這條特別簡單，但仍必須維持。**

## 7. 價格結算

```csharp
_pricing.RegisterCompletedOrders(本期 assign-order 移動數);
_pricing.RegisterDecision(
    boundOrders:  本期 assign-order 移動數,
    valuedOrders: 本期 assign-order 移動數 + valuedOnlyOrders,
    stratum:      StratifiedDelta ? min(Pb.Count, 3) : -1);
```

與 M4G-NS 的定義**逐字相同**。

🚨 **這條曾經出過錯**：舊 HGS-M4 餵錯 δ 的定義，導致它的 δ 停在 0.946 而 M4G 是 0.166——兩個模型名義上共用價目表，實際跑在完全不同的價格上。**驗收必須檢查兩臂的 δ 落在同一量級。**

# 修訂 v2（2026-08-09）：單一 complete-order 移動，取代 §3 的雙移動設計

## 為什麼要改

v1 把移動拆成「指派整單（要求該站台**已經**蓋得住）」＋「派**一台**車」。實測失敗：

| M5-NS(v1) vs HADGS，5 seeds | 差 | t |
|---|---|---|
| 完成訂單 | **−26.88%** | −7.53 顯著 |
| 件數 | −29.40% | −7.72 顯著 |
| EOR | −1.17% | −0.45 n.s. |

**診斷**：67.7% 的決策是完全 no-op；總派車 149 vs exact 176。

**根因**：整單原子下，**一張單常需多台貨架才蓋得住**。派一台車單獨解鎖不了任何訂單
⟹ 前瞻價值為零 ⟹ 拒絕派車 ⟹ 永遠湊不齊。

> **⟹ 移動原子必須對齊模型原子。** M5 的移動是「關掉這條線，含它需要的貨架」；
> M5-NS 的移動就該是「**完成這張單，含它需要的貨架**」。
> v1 那個分解破壞了整單原子——與 M4G-NS v1 的錯誤同類。

## v2 移動集合：只有一種

### complete-order(o, s)

**可行條件**
1. 訂單 *o* 尚未被指派（shi2）
2. 站台 *s* 尚有空槽（shi4；**硬約束**）
3. 「站台 *s* 現有庫存」∪「本期可派出的 *P^a* 貨架」能覆蓋 *o* 的**全部**需求（shi5）
4. 所需新派貨架數 ≤ 空閒機器人數（shi8/shi10；**硬約束**）

**貨架選擇**：先用站台現有庫存（沉沒，零成本），不足的部分以**貪婪集合覆蓋**補足——
每次挑「每公尺新覆蓋件數最高」的 *P^a* 貨架，配最近的空閒機器人。
標準貪婪集合覆蓋，**不引入任何手調參數**。

**計分**
```
Δ = Σ_{新派貨架 p}( D_rp + D_ps )        ← 只有新派的付路程，沉沒者為 0
    − μ(1−δ)                             ← yaos
    − μδ  ／ 或 0 若該單已被估值層計入     ← yos（FaithfulMarginal）
    − σ                                   ← 填掉一個空槽，σ = SlotScale × μ
```
即：`Δ = 新派路程 − μ − σ`（未被估值時）或 `新派路程 − μ(1−δ) − σ`（已被估值時）。

**接受最負的移動，直到沒有負的為止。**

## 解空間相容性（S-8 的前提，必須維持）

每個 complete-order 移動只設定 `x[p,s]=1`（所選貨架）、`u[r,p]=1`（其搬運者）、
`yaos[o,s]=1`、`yos[o,s]=1`——**全部落在 M4G-NS 的 shi2–shi13 內**。
因此 `obj(M5-NS) ≥ obj(M4G-NS)` 仍然成立，間隙可報告。

⚠️ **貪婪集合覆蓋可能挑到非最優的貨架組合**——那只會讓目標值更差，**不會逸出解空間**，
所以不破壞上述不等式。這正是「貪婪是同一問題的可行解」這個宣稱的內容。

## 其餘部分不變

§4（估值層 ValuationSweepNS，整單覆蓋、無槽位限制）、§5（σ 不需變數）、
§6（外層 μ 迭代，σ 必須隨 μ 同步縮放）、§7（價格結算）、§8（實作與硬性約束）全部沿用。
